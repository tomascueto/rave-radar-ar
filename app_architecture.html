De los scrapers al mapa: cómo funciona toda la app

Cinco capas, de la ingesta de datos al navegador: qué escribe qué, qué es determinístico y qué depende de un LLM. El Agente RAG está resumido acá — el detalle de sus 8 nodos de LangGraph está en rag_pipeline_architecture.html. Incluye el orquestador diario (run_pipeline.py) y el panel de administración (admin/router.py + AdminPage.jsx), protegido de punta a punta por is_admin. Hacé click en cualquier nodo para ver su detalle.

Seleccioná un nodo del diagrama para ver qué archivo lo implementa, qué hace, y qué lee o escribe.

Cómo leer el diagrama

Cinco capas, en el mismo orden que dibuja el README

Ingesta
scripts de scraper/, se corren a mano
Almacenamiento
Postgres+PostGIS (relacional) y Qdrant (vectorial)
Agente RAG
resumido — detalle completo en el otro diagrama
Backend API
FastAPI, un solo proceso (api_events.py + 3 routers, incluido admin)
Frontend
React + Vite, solo habla con el Backend API

El Backend API también lee/escribe PostgreSQL directamente para auth, preferencias y el mapa, sin pasar por el Agente RAG — esa es la flecha punteada de la izquierda.
